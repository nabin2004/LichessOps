\chapter{Pipeline planning and design (Exercise 1, Step 2)}
\label{ch:pipeline-planning}

Workloads split between interactive analytics (notebooks, exploratory SQL, BI artefacts) and an automated supervised-learning pipeline.
Planning therefore separates stable interfaces (configs, artefacts, lineage) from components that may change as data volume and SLA expectations evolve.

\section{Consumer obligations and guiding principles}
\label{sec:consumers-principles}

Primary consumers are analysts (ad hoc exploration on curated datasets) and ML engineers (scheduled training and promotion).
Non-functional targets include recoverability after partial runs, reproducible executions from recorded configs and artefact snapshots, auditability via lineage metadata, and clear escalation when ingestion blocks or deployments fail.

Toolchain assumptions mirror production-oriented stacks: orchestration akin to Kubeflow, ZenML, or TFX DAGs; object storage compatible with cloud-native ML workflows; and experiment registries where appropriate.
Operational ownership distinguishes data sourcing and landing-zone durability from modelling and deployment approvals.

\Cref{fig:etl-flow} summarises bucket-to-bucket ETL under Apache Airflow; \cref{fig:mlops-pipeline} follows a modular, configuration-driven layout common in TFX-, ZenML-, or Kubeflow-style projects.
Solid edges carry data and artefact dependencies; dashed edges mark execution ordering.
Raw data originates from \textbf{Lichess.org} (API export, bulk release, or other harvest) into \textbf{MinIO}, acting as versioned landing zone prior to deterministic downstream steps.

\textbf{Stage~A --- data ingestion.}
Inputs combine objects from MinIO with a \textit{data ingestion config} (endpoints, batch windows, partitioning).
Processing extracts structured slices (e.g.\ games, ratings metadata) into \textbf{data ingestion artefacts} (CSV/Parquet/TFRecord files under versioned prefixes).

\textbf{Stage~B --- data validation.}
The validator applies schema constraints, completeness thresholds and drift cues from \textit{data validation config}.
It emits \textbf{validation artefacts} (reports, anomaly logs); a feedback path supports retries or remediation before transformation consumes data.

\textbf{Stage~C --- data transformation.}
Feature rules from \textit{data transformation config} drive harmonisation, encoding, and scaling; the stage splits train / validation / test without leakage and exports \textbf{transformation artefacts} (tensor batches, fitted preprocessors serialised beside data).

\textbf{Stage~D --- model trainer.}
The trainer reads transformation bundles and hyperparameters from \textit{model trainer config}, runs the optimisation loop, and produces \textbf{trainer artefacts}: weight checkpoints, architecture descriptors, and scalar training logs.

\textbf{Stage~E --- model evaluation.}
Held-out splits and thresholds in \textit{model evaluation config} drive scoring; outputs may compare against production baselines and materialise \textbf{evaluation artefacts}: metric JSON, ROC summaries, and confusion-matrix exports.

\textbf{Conditional deployment.}
A \emph{model accepted?} gateway inspects evaluation artefacts and passes control only when every guardrail clears.
The \textbf{model pusher} consumes \textit{model pusher config} (registry URL, container image tagging, K8s namespace, or artefact buckets) and publishes \textbf{model pusher artefacts}: production bundles plus dependency manifests and inference schema contracts.

\textbf{Cross-cutting patterns.}
Configs stay decoupled from implementations; each stage writes immutable artefacts with metadata so failed runs expose exact intermediates, reproducible reruns traverse the same graph, and lineage tooling can relate predictions back to ingestion inputs.

\section{Data ingestion}
\label{sec:stage-ingestion}

\begin{figure}[htbp]
  \centering
  \includegraphics[width=\linewidth,height=0.85\textheight,keepaspectratio]{dataIngestion.pdf}
  \caption{Data ingestion: the orchestrator applies ingestion config, downloads Lichess monthly data to a raw-data bucket, validates checksums, decompresses with Zstandard, parses games, and writes processed Parquet; invalid payloads trigger alerts.}
  \label{fig:data-ingestion}
\end{figure}

\subsection{What \& dependencies}
Transport pulls from public Lichess releases or API surfaces into MinIO S3-compatible buckets, with partition keys reflecting batch date or export id.
Contracts cover file formats, hashing for deduplication, buffering between harvest jobs, watermark semantics for incremental loads, and lineage events emitted per successful land.

\subsection{Why it matters \& consumer impact}
Ingestion is the SLA root: gaps or duplication corrupt analytics dashboards and raise poisoning risk in labelled training shards, while stable prefixes let consumers pin reproducible snapshots.

\subsection{Responsible roles}
Data engineering owns connectors and landing durability; the ML platform curates ingestion templates; governance reviews external data licence alignment.

\subsection{How execution unfolds}
Scheduled jobs respect Lichess rate limits, hydrate MinIO, surface partial failures via alerting, declare bucket lifecycle policies as infrastructure-as-code, and rerun with idempotent object keys.

\section{Data pre-processing}
\label{sec:stage-preprocessing}

\begin{figure}[htbp]
  \centering
  \includegraphics[width=\linewidth,height=0.92\textheight,keepaspectratio]{dataValidation.pdf}
  \caption{Data validation under orchestration: train/test splits are checked for schema completeness and drift; Great Expectations stores validation reports; failures route to alerts and updated artefact keys, while validated processed data feeds an offline feature store.}
  \label{fig:data-validation}
\end{figure}

\subsection{Structural harmonisation \& quality assurance}
Stage~B enforces categorical domains, numeric ranges, temporal ordering, and anomaly budgets.
Stage~C materialises deterministic encoders, documents schema versions and anomaly handling policies, reconciles surrogate keys for slowly changing chess metadata, keeps deterministic features scriptable, and confines learnt embeddings to serialised artefacts.

\subsection{Human and automated actors}
Domain SMEs consult on adjudicated labels or rule tweaks; automated gates block downstream steps when anomaly density exceeds thresholds and open tickets to stewardship.

\subsection{Outputs feeding consumers}
Bronze aligns with validated raw-normalised payloads, silver hosts league-ready analytic tables, and modelling tensors sit adjacent to preprocessors so inference applies identical transforms.

\section{Model development}
\label{sec:stage-model-dev}

\begin{figure}[htbp]

  \includegraphics[width=\linewidth,height=0.85\textheight,keepaspectratio]{modelTrainer.pdf}

Experiment tracking binds git revisions, configs, and artefacts; MLflow (or equivalent) stores metrics per hyperparameter sweep.
Validation design keeps test data sequestered until final evaluation.
Responsible AI checkpoints include bias dashboards when sensitive attributes exist, and promotion artefacts bundle weights, optimiser states, and payloads for Stage~E.

\section{Model deployment}
\label{sec:stage-deployment}

\begin{figure}[htbp]
  \centering
  \includegraphics[width=\linewidth,height=0.85\textheight,keepaspectratio]{deployment.pdf}
  \caption{Deployment: promote a recent model from MLflow, build a Dockerised FastAPI image, run health checks, and push to the serving host (e.g.\ EC2); improved metrics can trigger CI/CD to refresh the endpoint.}

Packaging emits signed containers, ONNX exports, or TorchScript bundles; rollout supports blue-green or canary patterns; rollback re-pins registry tags.
Performance contracts define latency envelopes and throughput.
Model pusher artefacts integrate with ingress and feedback loops that tie score distributions to validation thresholds anchored in preprocessing.

\section{Model monitoring}
\label{sec:stage-monitoring}

\begin{figure}[htbp]
  \centering
  \includegraphics[width=\linewidth,height=0.85\textheight,keepaspectratio]{monitoringObserv.pdf}
  \caption{Monitoring and observability: API metrics scraped by Prometheus, dashboards and automated reports, rule-based routing to Slack/PagerDuty/email, and controlled reruns from user or scheduled inputs.}
  \label{fig:monitoring}
\end{figure}

Production monitors drift in input features, calibration of predicted strengths, and score-prediction error against fresh labelled games.
Alerting flows through on-call rotations; human review queues escalate fairness or unfair-play detectors; lineage metadata ties retrains to prior artefact identifiers.
Scheduled reviews or threshold breaches trigger reruns whose inputs remain traceable to MinIO ingestion boundaries.
