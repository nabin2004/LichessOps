\section{Dimension Tables Overview}
Our database has star schema which contains the following dimension tables as show in figure ~\ref{fig:describe_other_tables} 

% The \texttt{dim\_player} table stores information about each unique chess player 
% identified by a \texttt{player\_id}. The \texttt{username} column holds the player's Lichess 
% handle, while \texttt{title} (e.g., FM, IM, GM) records any official title. 
% \texttt{last\_known\_elo} is a slowly changing attribute that captures the player's most 
% recent rating; this approach avoids updating every historical game record when a 
% rating changes.

% The \texttt{dim\_opening} table maps each \texttt{opening\_id} to its \texttt{eco} code (e.g., B30, C50) 
% and a human-readable \texttt{opening\_name}. This separation allows the fact table to 
% reference only the compact opening identifier, saving space and enabling 
% consistency across millions of games.

% Finally, \texttt{dim\_date} provides a time dimension with \texttt{date\_id} (a surrogate key), 
% \texttt{calendar\_date}, \texttt{year}, \texttt{month}, and \texttt{day\_of\_week}. This design supports time-based 
% analyses such as monthly win-rate trends or day-of-week performance comparisons 
% without repeatedly storing full date strings in the fact table.

% Together, these dimension tables enforce referential integrity and greatly 
% improve query performance for analytical workloads, as joins are performed only 
% on compact integer or short string keys.

\section{Model Drift}
Model drift is a condition inferencing model in production comes from data which is out of training data distribution. In our pipeline, this can occur when new type of opening startegy get's popular among players level due to several reasons like a new chess engine discovered best move or a grand master popularised a new opening strategy. 
% To mathematically characterise the operational environment, the data-generating process at any given temporal point \(t\) is defined as a joint probability distribution \(P_{t}(X, Y)\) over the input covariate space \(X\) and the target output space \(Y\)~\cite{gama2014}. The joint probability distribution is decomposed into a marginal distribution of the features \(P(X)\) and a conditional distribution of the target given the features \(P(Y|X)\), expressed as \(P(X,Y) = P(X) \cdot P(Y|X)\)~\cite{gama2014}. Model drift occurs when the joint distribution at a specific production time step \(t+1\) deviates from the baseline training distribution at time \(t\), such that \(P_{t+1}(X,Y) \neq P_{t}(X,Y)\)~\cite{webb2018}. This overall distribution shift is segmented into three distinct statistical phenomena~\cite{gama2014, webb2018}:

% \begin{itemize}
%     \item \textbf{Covariate Shift (Virtual Drift)}: This shift occurs when the marginal distribution of the input features changes over time, while the conditional probability mapping features to target labels remains stationary, written as \(P_{t+1}(X) \neq P_{t}(X)\) and \(P_{t+1}(Y|X) = P_{t}(Y|X)\)~\cite{shimodaira2000}. Formulated initially by Shimodaira in 2000, covariate shift assumes that the training data and operational test data are drawn from different distributions, yet the underlying decision rules remain constant~\cite{shimodaira2000}. For example, if a chess platform experiences a massive influx of novice players, the marginal distribution of user ratings \(P(X)\) shifts significantly downward, yet the underlying relationship between rating differences and game outcomes \(P(Y|X)\) remains invariant~\cite{microsoft2022}.

%     \item \textbf{Real Concept Drift (Posterior Shift)}: This shift occurs when the relationship between the input features and the target variable changes over time, regardless of any changes in the marginal distribution of the covariates, written as \(P_{t+1}(Y|X) \neq P_{t}(Y|X)\) and \(P_{t+1}(X) = P_{t}(X)\)~\cite{webb2018}. This represents a physical alteration of the optimal decision boundary~\cite{webb2018}. In a chess analytics context, if a server-side engine update or major patch modifies the automated positional assessment of board states, a specific feature vector \(x\) representing a pawn structure may now map to a different victory probability \(P(Y|x)\), shifting \(P(Y|X)\) without altering the frequency of the board states themselves~\cite{ibm_drift}.

%     \item \textbf{Prior Probability Shift (Label Drift)}: This shift manifests when the marginal distribution of the target variable changes over time while the class-conditional distributions remain constant, written as \(P_{t+1}(Y) \neq P_{t}(Y)\) and \(P_{t+1}(X|Y) = P_{t}(X|Y)\)~\cite{webb2018}. This occurs when the overall proportion of class outcomes changes~\cite{webb2018}. For instance, a sudden surge in player reports or flaggings during a seasonal competitive event skew the baseline expectation of the proportion of anomalous accounts, requiring models to adjust classification thresholds to prevent false positives~\cite{lichess2025}.
% \end{itemize}

\subsection{Concept Drift}
Concept drift is a specific type of model drift where the underlying relationship between input features and the target variable changes over time. In our MLOps pipeline, concept drift could occur if Chess Federation decides to change the rules or introduce new rules. 

\subsection{Drift Mitigation Strategies for the Pipeline}
We mainly employ the two strategies for mitigating the model drift. First, we run monitoring daily to check the distribution. Second, we retrain the model on newer data every month whenever the distribution shift is detected.
